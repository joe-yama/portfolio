# Spec Delta

## ADDED Requirements

### Requirement: トップページの仕事の一行

トップページは、名前の直後に、そのロケールのプロフィールの `headline` を表示しなければならない（MUST）。`tagline` は `headline` の後ろに表示する（MUST）。

#### Scenario: 日本語トップの仕事の一行

- **WHEN** `/ja/` を表示する
- **THEN** 名前の見出しの次に `profile/ja.yaml` の `headline` が現れ、その次に `tagline` が現れる

#### Scenario: 英語トップの仕事の一行

- **WHEN** `/en/` を表示する
- **THEN** 名前の見出しの次に `profile/en.yaml` の `headline` が現れる

### Requirement: 広い画面でのトップページの横並び

幅 64rem 以上の画面では、トップページは代表写真を左に、名前・仕事の一行・肩書・サイト内の導線・連絡先リンクを右に並べなければならない（MUST）。代表写真の右端は、右側の文字列のいずれの左端よりも左になければならない（MUST）。横位置の代表写真の表示幅は、本文の幅の半分以上でなければならない（MUST）。

幅 64rem 未満の画面では、代表写真を上に、名前以下を下に並べなければならない（MUST）。

この並びは CSS だけで実現し、JavaScript を使ってはならない（MUST NOT）。

#### Scenario: PC 幅の横並び（1280×720）

- **WHEN** 幅 1280px・高さ 720px の画面で横位置の代表写真を持つ `/ja/` を開く
- **THEN** 代表写真の右端は名前・仕事の一行・肩書・導線・連絡先リンクの左端より左にあり、代表写真の表示幅は `main` の幅の半分以上である

#### Scenario: 境目の幅（1024px）

- **WHEN** 幅 1024px・高さ 768px の画面で `/en/` を開く
- **THEN** 代表写真の右端は名前の左端より左にある

#### Scenario: 境目より狭い幅（1023px）

- **WHEN** 幅 1023px・高さ 768px の画面で `/ja/` を開く
- **THEN** 代表写真の下端は名前の上端より上にある

#### Scenario: スマホ幅

- **WHEN** 幅 390px・高さ 844px の画面で `/ja/` を開く
- **THEN** 代表写真の下端は名前の上端より上にあり、横スクロールは発生しない

## MODIFIED Requirements

### Requirement: トップページの初見表示

幅 1280px・高さ 720px 以上の画面でトップページを開いたとき、代表写真・名前・仕事の一行・肩書・連絡先リンクのすべて・サイト内の導線のすべては、スクロールせずに見えなければならない（MUST）。ヘッダーとフッターはこの条件の対象外とする。

この条件は両ロケールで満たされなければならない（MUST）。ロケールごとの文字列の長さの違いによってこの条件が破れてはならない（MUST NOT）。

#### Scenario: 日本語トップ（1280×720）

- **WHEN** 幅 1280px・高さ 720px の画面で `/ja/` を開く
- **THEN** 代表写真・名前・仕事の一行・肩書・すべての連絡先リンク・すべてのサイト内の導線の下端は、いずれも画面の下端より上にある

#### Scenario: 英語トップ（1280×720）

- **WHEN** 幅 1280px・高さ 720px の画面で `/en/` を開く
- **THEN** 代表写真・名前・仕事の一行・肩書・すべての連絡先リンク・すべてのサイト内の導線の下端は、いずれも画面の下端より上にある

#### Scenario: 広い画面（1440×900）

- **WHEN** 幅 1440px・高さ 900px の画面で `/ja/` と `/en/` を開く
- **THEN** いずれのロケールでも、代表写真・名前・仕事の一行・肩書・すべての連絡先リンク・すべてのサイト内の導線の下端は画面の下端より上にある

#### Scenario: 横並びの境目（1024×768）

- **WHEN** 幅 1024px・高さ 768px の画面で `/ja/` と `/en/` を開く
- **THEN** いずれのロケールでも、代表写真・名前・仕事の一行・肩書・すべての連絡先リンク・すべてのサイト内の導線の下端は画面の下端より上にある

### Requirement: 経歴ページ

ビルド出力は `/ja/career/` と `/en/career/` を含まなければならない（MUST）。経歴ページは、最上位の見出しの直後に経歴の要約を置き、その後に職歴・スキル・資格・実績・特許の 5 つの区画をこの順で持たなければならない（MUST）。要約は `highlights` の各項目をデータに書かれた順の箇条書きとして表示し、区画の見出しを持ってはならない（MUST NOT）。ページの `<title>` のページ名と見出しは両ロケールとも `Career` とする（MUST）。区画の見出しはロケールごとの文字列とする（MUST）。

#### Scenario: 経歴ページの出力

- **WHEN** ビルドする
- **THEN** `dist/ja/career/index.html` と `dist/en/career/index.html` が存在する

#### Scenario: ページ名と見出し

- **WHEN** `/ja/career/` を表示する
- **THEN** `<title>` は `Career · <プロフィールの名前>`、ページの最上位の見出しは `Career` である

#### Scenario: 区画の順序

- **WHEN** `/en/career/` を表示する
- **THEN** 職歴・スキル・資格・実績・特許の見出しがこの順で現れる

#### Scenario: 経歴の要約

- **WHEN** `highlights` が 4 件の状態で `/ja/career/` を表示する
- **THEN** 最上位の見出し `Career` と職歴の区画の見出しのあいだに、4 件がデータに書かれた順の箇条書きとして現れ、そのあいだに他の見出しは無い

### Requirement: 資格と実績の表示

資格と実績は、それぞれ `date` の新しい順に並べなければならない（MUST）。年月までの日付（`YYYY-MM`）は、その月の 1 日と同じ位置に置かなければならない（MUST）。並びの中で同じ位置になる項目どうしは、データに書かれた順を保たなければならない（MUST）。

各項目は日付と名前を表示しなければならない（MUST）。日付は書かれた粒度のまま、ロケールに応じた表記で表示しなければならない（MUST）。年月までの日付に日を補って表示してはならない（MUST NOT）。

`group` を持つ資格は、同じ `group` の資格ごとに 1 項目にまとめて表示しなければならない（MUST）。まとめた項目は、そのグループで最も新しい `date` を持つ資格の位置に置く（MUST）。まとめた項目は、期間、グループ名、件数を表示しなければならない（MUST）。期間はグループで最も古い `date` と最も新しい `date` を、書かれた粒度のままロケールに応じた表記で「古い – 新しい」の形に並べ、両者が同じ場合は 1 つだけ表示する（MUST）。件数は日本語では `（N 件）`、英語では ` (N)` の形でグループ名の後ろに付ける（MUST）。まとめた項目の内訳（各資格の日付と名前。並びと `url` の扱いは上の規則どおり）は、既定では折りたたまれ、利用者の操作で同じページ内に展開できなければならない（MUST）。内訳は JavaScript を実行しない環境でもビルド出力の HTML に含まれていなければならず（MUST）、展開に JavaScript を使ってはならない（MUST NOT）。`group` を持たない資格は、これまでどおり 1 件ずつ表示する（MUST）。

実績は種別（登壇・執筆・受賞・その他）をロケールごとの文字列で表示しなければならない（MUST）。`url` を持つ項目だけを、その `url` へのリンクにしなければならない（MUST）。`url` を持たない項目をリンクにしてはならない（MUST NOT）。

#### Scenario: 新しい順に並ぶ

- **WHEN** `date` が `2023-06-01` と `2024-10-12` の実績がある状態で `/ja/career/` を表示する
- **THEN** `2024-10-12` の項目が先に現れる

#### Scenario: 粒度が混ざった並び

- **WHEN** `date` が `2025-10`、`2025-09-30`、`2025-11-01` の 3 件がある状態で `/ja/career/` を表示する
- **THEN** `2025-11-01`、`2025-10`、`2025-09-30` の順に現れる

#### Scenario: 同じ位置になる項目

- **WHEN** `date` が `2016-03` の項目 A と `2016-03-01` の項目 B を、データにこの順で書いた状態で `/ja/career/` を表示する
- **THEN** A が B より先に現れる

#### Scenario: 年月までの日付（日本語）

- **WHEN** `date` が `2025-10` の資格を `/ja/career/` に表示する
- **THEN** `2025年10月` と表示され、`1日` は現れない

#### Scenario: 年月までの日付（英語）

- **WHEN** 同じ資格を `/en/career/` に表示する
- **THEN** `October 2025` と表示される

#### Scenario: 年月日までの日付（日本語）

- **WHEN** `date` が `2017-08-31` の実績を `/ja/career/` に表示する
- **THEN** `2017年8月31日` と表示される

#### Scenario: 年月日までの日付（英語）

- **WHEN** 同じ実績を `/en/career/` に表示する
- **THEN** `August 31, 2017` と表示される

#### Scenario: 種別のラベル（日本語）

- **WHEN** `kind` が `talk` の実績を `/ja/career/` に表示する
- **THEN** `登壇` と表示される

#### Scenario: 種別のラベル（英語）

- **WHEN** 同じ実績を `/en/career/` に表示する
- **THEN** `Talk` と表示される

#### Scenario: リンクの有無

- **WHEN** `url` を持つ実績と持たない資格を表示する
- **THEN** 実績の名前は `url` へのリンクになり、資格の名前はリンクにならない

#### Scenario: 資格を束ねる（日本語）

- **WHEN** `group` が `AWS 認定` の資格が `2025-04` から `2025-10` のあいだに 12 件ある状態で `/ja/career/` を表示する
- **THEN** 資格の区画には `2025年4月 – 2025年10月` と `AWS 認定（12 件）` を含む項目が 1 つだけ現れ、12 件の名前は折りたたまれた内訳の中にある

#### Scenario: 資格を束ねる（英語）

- **WHEN** 同じデータで `/en/career/` を表示する
- **THEN** `April 2025 – October 2025` と `AWS Certifications (12)` を含む項目が 1 つだけ現れる

#### Scenario: まとめた項目の位置

- **WHEN** `date` が `2026-05` の資格 A、`group` が `AWS 認定` で `date` が `2025-04` と `2025-10` の資格 2 件、`date` が `2020-07` の資格 B がある状態で `/ja/career/` を表示する
- **THEN** A、AWS 認定のまとめた項目、B の順に 3 項目が現れる

#### Scenario: 内訳を開く

- **WHEN** `/ja/career/` でまとめた項目を操作して展開する
- **THEN** そのグループの資格の名前がすべて、`date` の新しい順に見える

#### Scenario: 期間が 1 か月だけのグループ

- **WHEN** `group` が同じ資格 2 件の `date` がどちらも `2025-10` の状態で `/ja/career/` を表示する
- **THEN** まとめた項目の期間は `2025年10月` だけで、` – ` を含まない
