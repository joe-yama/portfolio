## MODIFIED Requirements

### Requirement: 写真の入稿コマンド
リポジトリは写真 1 枚を入稿するコマンド `pnpm photo:add <画像ファイル>` を提供しなければならない（MUST）。コマンドは次をこの順で行わなければならない（MUST）。

1. 引数を解釈する。必要な引数が無ければ、使い方を示して中断する（MUST）
2. GitHub の認証済みアカウントを確認する。`joe-yama` でなければ、何も変更せずに中断する（MUST）
3. 元画像から撮影情報（撮影日、カメラ、レンズ、絞り、シャッター速度、ISO 感度）を読み取る
4. 元画像を長辺 2500px 以下・sRGB・JPEG 品質 90 に変換する。元画像の長辺が 2500px 以下の場合は拡大してはならない（MUST NOT）
5. 変換した画像を Release `photos` の `<slug>.jpg` として登録する。同名の asset があれば置き換える（MUST）。Release が存在しなければ作成する
6. `<slug>` の写真データファイルが**存在しない場合に限り**生成する。`image` の URL、撮影日、撮影情報の 5 項目を埋め、`order` は既存の最大値より後ろ、`featured` は既存に代表写真が無いときのみ真とする。タイトル・撮影地・代替テキストは人が記入する欄として、未記入であることが分かる印を入れる（MUST）

`<slug>` の写真データファイルが既に存在する場合、コマンドはそれを書き換えてはならない（MUST NOT）。この場合は写真の差し替えとして扱い、画像の登録だけを行ったことと、データファイルを変更していないことを示して正常終了しなければならない（MUST）。あわせて、差し替えた画像の古い版がビルド出力に残らないよう、ビルドの画像キャッシュを無効化しなければならない（MUST）。

撮影情報を読み取れない項目があった場合は、その項目名を示して中断しなければならない（MUST）。項目名は本仕様の語彙（撮影日、カメラ、レンズ、絞り、シャッター速度、ISO 感度）で示さなければならない（MUST）。

slug は、明示的に指定された場合はその値をそのまま使わなければならない（MUST）。指定が無い場合に限り、元画像のファイル名から拡張子を除いて導かなければならない（MUST）。

引数が解釈できないとき（未知のオプションなど）と、slug が使えない値のとき（パス区切りを含む、先頭または末尾が `.` など）は、他の中断と同じ体裁の 1 行で理由を示して中断しなければならない（MUST）。この場合、スタックトレースを出してはならず（MUST NOT）、GitHub への問い合わせを行う前に中断しなければならない（MUST）。

元画像を画像として読めないとき（画像でないファイル、壊れた画像など）は、他の中断と同じ体裁の 1 行で理由を示して中断しなければならない（MUST）。この場合、読み取りに使った部品の内部情報やスタックトレースを出してはならず（MUST NOT）、Release にも作業ツリーにも変更を加えてはならない（MUST NOT）。

`gh` の実行に失敗したとき（未ログイン、ネットワーク断など）は、他の中断と同じ体裁の 1 行で理由を示して中断しなければならない（MUST）。Release の有無の判定に、Release が無いこと以外の失敗を含めてはならない（MUST NOT）。

#### Scenario: 認証アカウントが違う
- **WHEN** GitHub の認証済みアカウントが `joe-yama` ではない状態で `pnpm photo:add` を実行する
- **THEN** コマンドは中断し、Release にも作業ツリーにも変更を加えない

#### Scenario: 引数が無い
- **WHEN** 画像ファイルを渡さずに `pnpm photo:add` を実行する
- **THEN** GitHub への問い合わせを行う前に使い方を示して中断する

#### Scenario: カメラ出力の JPEG を入稿する
- **WHEN** 長辺 6000px の JPEG を `pnpm photo:add` に渡す
- **THEN** Release `photos` に長辺 2500px の `<slug>.jpg` が登録され、写真データファイルが生成される
- **AND** 生成されたファイルの `image` は `https://github.com/joe-yama/portfolio/releases/download/photos/<slug>.jpg` である

#### Scenario: 入稿規定より小さい画像
- **WHEN** 長辺 1600px の JPEG を渡す
- **THEN** 拡大されず、長辺 1600px のまま登録される

#### Scenario: 2 枚目以降の入稿
- **WHEN** 既に代表写真が 1 枚ある状態で新しい写真を入稿する
- **THEN** 生成されるファイルの `featured` は偽であり、`order` は既存のどの写真よりも後ろになる

#### Scenario: 同じ slug で写真を差し替える
- **WHEN** 人が `title` / `location` / `alt` を記入済みの写真と同じ slug で `pnpm photo:add` を実行する
- **THEN** Release の画像は新しい画像に置き換わり、写真データファイルは 1 文字も変わらない
- **AND** データファイルを変更していないことが出力に示され、終了コードは 0 である

#### Scenario: 差し替え後のビルド
- **WHEN** 同じ slug で写真を差し替えた直後にビルドする
- **THEN** ビルド出力の画像は新しい画像から生成されたものであり、古い版は残らない

#### Scenario: slug を明示する
- **WHEN** 拡張子に見える文字列を含む slug（`kamo-river-v1.2` など）を明示して入稿する
- **THEN** その値がそのまま slug として使われ、切り詰められない

#### Scenario: 撮影情報が欠けている
- **WHEN** レンズ情報を持たない JPEG を渡す
- **THEN** コマンドは「レンズ」が欠けていることを示して中断する

#### Scenario: 使えない slug
- **WHEN** `--slug ../../x` または `--slug kamo-river.` を指定して `pnpm photo:add` を実行する
- **THEN** GitHub への問い合わせを行う前に、slug が使えないことを示す 1 行を出して中断し、スタックトレースは出ない

#### Scenario: 未知のオプション
- **WHEN** `--sulg kamo` のように未知のオプションを指定して `pnpm photo:add` を実行する
- **THEN** 未知のオプションであることを示す 1 行と使い方を出して中断する

#### Scenario: 画像として読めないファイル
- **WHEN** 拡張子が `.jpg` のテキストファイルを `pnpm photo:add` に渡す
- **THEN** 画像として読めないことを示す 1 行を出して中断し、スタックトレースや読み取り部品の内部情報は出ず、Release にも作業ツリーにも変更は無い
