## ADDED Requirements

### Requirement: 開発物のデータ構造

開発物は 1 件につき 1 ファイルで、ファイル名（拡張子を除く）を slug とする。各開発物は次の項目を持たなければならない（MUST）。

- `order`: 整数。ページでの並び順
- `name`: 空でない文字列。両ロケールで共通の名前
- `url`: URL 形式。公開先
- `icon`: サイトが定義する開発物のアイコン名のいずれか。定義に無い名前はビルドを失敗させなければならない（MUST）
- `since`: 4 桁の西暦の整数。開発を始めた年
- `status`、`summary`、`description`: それぞれ `ja` と `en` の両方を持つ空でない文字列
- `tech`: 空でない文字列の配列で 1 件以上

開発物のコレクション全体で、開発物は 1 件以上なければならず（MUST）、`order` の値は重複してはならない（MUST NOT）。違反はビルドを失敗させ、`order` の重複では重複した値と該当する slug をすべて示さなければならない（MUST）。

#### Scenario: 必須項目が揃った開発物

- **WHEN** 上記の全項目を持つ開発物 1 件でビルドする
- **THEN** ビルドは成功する

#### Scenario: summary の英語が欠けた開発物

- **WHEN** `summary` に `ja` だけを持つ開発物でビルドする
- **THEN** ビルドは失敗する

#### Scenario: 未定義のアイコン名

- **WHEN** `icon` が `rocket`（定義に無い名前）の開発物でビルドする
- **THEN** ビルドは失敗する

#### Scenario: tech が空

- **WHEN** `tech` が空の配列の開発物でビルドする
- **THEN** ビルドは失敗する

#### Scenario: since の形式が違う

- **WHEN** `since` が `26` または `2026-09` の開発物でビルドする
- **THEN** ビルドは失敗する

#### Scenario: order が重複

- **WHEN** 2 件の開発物が同じ `order` を持つ
- **THEN** ビルドは失敗し、エラーに重複した値と両方の slug が含まれる

#### Scenario: 開発物が 0 件

- **WHEN** 開発物のファイルが 1 つも無い状態でビルドする
- **THEN** ビルドは失敗し、エラーに開発物が無いことが示される
