# photo-pipeline Specification

## Purpose

撮影した写真を、元画像を git に入れずに公開できるようにする。入稿（縮小・登録・雛形の生成）から、ギャラリー・個別ページ・トップの代表写真としての表示まで、写真がサイトに載るまでの一連の流れを定める。

## Requirements

### Requirement: 写真の並び順
写真の一覧は `order` の昇順で提供されなければならない（MUST）。ギャラリーの並び、個別ページの前後関係は、すべてこの同じ並びに従わなければならない（MUST）。

#### Scenario: order の昇順に並ぶ
- **WHEN** `order` が 30、10、20 の 3 枚の写真がある
- **THEN** 一覧は `order` が 10、20、30 の順で返る

#### Scenario: ギャラリーと前後関係が同じ並びを使う
- **WHEN** ギャラリーに表示される写真の順が A → B → C である
- **THEN** B の個別ページの「前」は A、「次」は C である

### Requirement: ギャラリーページ
各ロケールに写真の一覧ページ `/<locale>/photos/` が存在しなければならない（MUST）。一覧はすべての写真をその言語の代替テキスト付きで表示し、各写真はその写真の個別ページへのリンクでなければならない（MUST）。

写真は元の縦横比のまま表示されなければならず、切り抜いてはならない（MUST NOT）。キャプション（タイトル・撮影地・撮影情報）を一覧に表示してはならない（MUST NOT）。

#### Scenario: 日本語のギャラリー
- **WHEN** 訪問者が `/ja/photos/` を開く
- **THEN** 登録されているすべての写真が `order` 昇順で表示され、各写真は `/ja/photos/<slug>/` へのリンクになっている
- **AND** 各画像の代替テキストはその写真の日本語の `alt` である

#### Scenario: 英語のギャラリー
- **WHEN** 訪問者が `/en/photos/` を開く
- **THEN** 同じ写真が同じ順で表示され、各画像の代替テキストは英語の `alt`、リンク先は `/en/photos/<slug>/` である

#### Scenario: 縦位置と横位置が混在する
- **WHEN** 縦長の写真と横長の写真が一覧に含まれる
- **THEN** それぞれが元の縦横比のまま表示され、切り抜かれない

### Requirement: 写真の個別ページ
各写真について、各ロケールに個別ページ `/<locale>/photos/<slug>/` が存在しなければならない（MUST）。個別ページは写真 1 枚に加えて、そのロケールのタイトル・撮影地、撮影日、および撮影情報の 1 行を表示しなければならない（MUST）。

撮影情報の 1 行は `カメラ · レンズ · f/<絞り> · <シャッター速度> · ISO <感度>` の形式でなければならない（MUST）。撮影日はロケールに応じた表記でなければならない（MUST）。

個別ページはギャラリーへ戻るリンクを持たなければならない（MUST）。

#### Scenario: 日本語の個別ページ
- **WHEN** 訪問者が `/ja/photos/<slug>/` を開く
- **THEN** その写真、日本語のタイトルと撮影地、撮影日、撮影情報の 1 行、`/ja/photos/` へ戻るリンクが表示される

#### Scenario: 撮影情報の表示形式
- **WHEN** 写真の `exif` が camera `Fujifilm X-T5`、lens `XF 23mm F1.4 R LM WR`、aperture `1.4`、shutterSpeed `1/250`、iso `800` である
- **THEN** 撮影情報の行は `Fujifilm X-T5 · XF 23mm F1.4 R LM WR · f/1.4 · 1/250 · ISO 800` と表示される

#### Scenario: 撮影日のロケール別表記
- **WHEN** `takenAt` が 2025-11-03 である
- **THEN** 日本語ページでは `2025年11月3日`、英語ページでは `November 3, 2025` と表示される

### Requirement: 写真の個別ページの初見表示

幅 1280px・高さ 720px 以上の画面で写真の個別ページを開いたとき、写真・タイトル・撮影地・撮影日・撮影情報の 1 行は、スクロールせずにすべて見えなければならない（MUST）。前後の写真への移動とギャラリーへ戻るリンクは、この条件の対象外とする。

#### Scenario: 縦位置の写真（1280×720）

- **WHEN** 幅 1280px・高さ 720px の画面で縦位置の写真の個別ページを両ロケールで開く
- **THEN** 写真・タイトル・撮影地・撮影日・撮影情報の下端は、いずれも画面の下端より上にある

#### Scenario: 縦位置の写真（1440×900）

- **WHEN** 幅 1440px・高さ 900px の画面で縦位置の写真の個別ページを両ロケールで開く
- **THEN** 写真・タイトル・撮影地・撮影日・撮影情報の下端は、いずれも画面の下端より上にある

### Requirement: 前後の写真への移動
個別ページは、並び順で隣接する写真の個別ページへのリンクを持たなければならない（MUST）。リンク先は同じロケールの個別ページでなければならない（MUST）。

並び順の先頭の写真には「前」のリンクを、末尾の写真には「次」のリンクを出してはならない（MUST NOT）。

#### Scenario: 中間の写真
- **WHEN** 並び順が A → B → C で、訪問者が B の個別ページを開く
- **THEN** A へのリンクと C へのリンクの両方が表示される

#### Scenario: 先頭の写真
- **WHEN** 訪問者が A（並び順の先頭）の個別ページを開く
- **THEN** 「前」のリンクは表示されず、「次」のリンク（B）とギャラリーへ戻るリンクは表示される

#### Scenario: 末尾の写真
- **WHEN** 訪問者が C（並び順の末尾）の個別ページを開く
- **THEN** 「次」のリンクは表示されず、「前」のリンク（B）とギャラリーへ戻るリンクは表示される

### Requirement: トップページの代表写真
各ロケールのトップページは、`featured: true` の写真を表示しなければならない（MUST）。代表写真はそのロケールの代替テキストを持ち、ページの読み込み開始時点で優先して取得されなければならない（MUST）。

代表写真が存在しない場合はビルドを失敗させなければならない（MUST）。

#### Scenario: 代表写真が表示される
- **WHEN** 訪問者が `/ja/` を開く
- **THEN** `featured: true` の写真が表示され、その代替テキストは日本語の `alt` である

#### Scenario: 代表写真が無い
- **WHEN** どの写真も `featured: true` を持たない状態でビルドする
- **THEN** ビルドは失敗する

### Requirement: 写真の表示高さの上限

トップページの代表写真と写真の個別ページの写真は、表示領域の高さに応じた上限を持たなければならない（MUST）。上限にかかった写真は、元画像の縦横比を保ったまま全体を表示しなければならず（MUST）、一部を切り取って表示してはならない（MUST NOT）。上限にかかって幅が表示領域より狭くなった写真は、左右の中央に置かれなければならない（MUST）。

ギャラリー一覧のサムネイルはこの上限の対象外とし、グリッドの列の幅いっぱいに表示しなければならない（MUST）。

画面の高さが極端に小さい場合でも、写真の表示高さが 0 になってはならない（MUST NOT）。

#### Scenario: 横位置の代表写真

- **WHEN** 幅 1440px・高さ 900px の画面で `/ja/` を開く
- **THEN** 代表写真の表示上の縦横比は元画像の縦横比と一致し、写真の下端は画面の下端より上にある

#### Scenario: 縦位置の写真の個別ページ

- **WHEN** 幅 1440px・高さ 900px の画面で縦位置の写真の個別ページを開く
- **THEN** 写真の表示上の縦横比は元画像の縦横比と一致し、写真の表示高さは画面の高さより小さい

#### Scenario: 写真が切り取られない

- **WHEN** 上限にかかった写真の表示上の幅と高さの比を、元画像の幅と高さの比と比べる
- **THEN** 両者は一致する（引き伸ばしも切り取りも起きていない）

#### Scenario: ギャラリーのサムネイル

- **WHEN** 幅 1440px・高さ 900px の画面でギャラリー一覧を開く
- **THEN** 各サムネイルの表示幅はグリッドの列の幅と一致する

#### Scenario: 狭い画面

- **WHEN** 幅 390px・高さ 844px の画面でトップページと写真の個別ページを開く
- **THEN** 写真は本文の幅いっぱいに表示され、横スクロールは発生しない

### Requirement: 写真画像の最適化と配信
写真の元画像はビルド時に取得され、最適化された派生画像として出力に含まれなければならない（MUST）。公開されたページが参照する画像は、すべて同一オリジンでなければならない（MUST）。

各画像は複数の幅と、AVIF・WebP の近代的な形式に加えて従来形式の代替を提供しなければならない（MUST）。用途ごとの目標幅は次のとおりとする（MUST）。

| 用途 | 目標幅 |
|---|---|
| ギャラリーの一覧 | 400 / 800 / 1200 |
| 個別ページ・トップの代表写真 | 1200 / 1800 / 2500 |

元画像より大きい幅の画像を生成してはならない（MUST NOT）。目標幅が元画像の幅を超える場合は、元画像の幅で打ち切らなければならない（MUST）。

すべての画像は、読み込み前から占有領域が決まるよう寸法を持たなければならない（MUST）。ギャラリーの画像は遅延読み込みでなければならず（MUST）、トップの代表写真は遅延読み込みにしてはならない（MUST NOT）。

出力される画像から撮影時のメタデータ（EXIF）は取り除かれていなければならない（MUST）。

#### Scenario: 同一オリジンからの配信
- **WHEN** ビルド出力の HTML を検査する
- **THEN** 画像の参照先に外部ホストは含まれず、すべてビルド出力に含まれるパスである

#### Scenario: 元画像が取得できない
- **WHEN** 写真の `image` が指す元画像を取得できない状態でビルドする
- **THEN** ビルドは失敗する

#### Scenario: 位置情報が漏れない
- **WHEN** 出力された画像のメタデータを検査する
- **THEN** 撮影時の EXIF（位置情報を含む）は含まれていない

### Requirement: 写真の入稿コマンド
リポジトリは写真 1 枚を入稿するコマンド `pnpm photo:add <画像ファイル>` を提供しなければならない（MUST）。コマンドは次をこの順で行わなければならない（MUST）。

1. 引数を解釈する。必要な引数が無ければ、使い方を示して中断する（MUST）
2. GitHub の認証済みアカウントを確認する。`joe-yama` でなければ、何も変更せずに中断する（MUST）
3. 元画像から撮影情報（撮影日、カメラ、レンズ、絞り、シャッター速度、ISO 感度）を読み取る
4. 元画像を長辺 2500px 以下・sRGB・JPEG 品質 90 に変換する。元画像の長辺が 2500px 以下の場合は拡大してはならない（MUST NOT）
5. 変換した画像を Release `photos` の `<slug>.jpg` として登録する。同名の asset があれば置き換える（MUST）。Release が存在しなければ作成する
6. `<slug>` の写真データファイルが**存在しない場合に限り**生成する。`image` の URL、撮影日、撮影情報の 5 項目を埋め、`order` は既存の最大値より後ろ、`featured` は既存に代表写真が無いときのみ真とする。タイトル・撮影地・代替テキストは人が記入する欄として、未記入であることが分かる印を入れる（MUST）

`<slug>` の写真データファイルが既に存在する場合、コマンドはそれを書き換えてはならない（MUST NOT）。この場合は写真の差し替えとして扱い、画像の登録だけを行ったことと、データファイルを変更していないことを示して正常終了しなければならない（MUST）。あわせて、差し替えた画像の古い版がビルド出力に残らないよう、ビルドの画像キャッシュを無効化しなければならない（MUST）。

撮影情報を読み取れない項目があった場合は、その項目名を示して中断しなければならない（MUST）。項目名は本仕様の語彙（撮影日、カメラ、レンズ、絞り、シャッター速度、ISO 感度）で示さなければならない（MUST）。

slug は、明示的に指定された場合はその値をそのまま使わなければならない（MUST）。指定が無い場合に限り、元画像のファイル名から拡張子を除いて導かなければならない（MUST）。

`gh` の実行に失敗したとき（未ログイン、ネットワーク断など）は、他の中断と同じ体裁の 1 行で理由を示して中断しなければならない（MUST）。Release の有無の判定に、Release が無いこと以外の失敗を含めてはならない（MUST NOT）。

#### Scenario: 認証アカウントが違う
- **WHEN** GitHub の認証済みアカウントが `joe-yama` ではない状態で `pnpm photo:add` を実行する
- **THEN** コマンドは中断し、Release にも作業ツリーにも変更を加えない

#### Scenario: 引数が無い
- **WHEN** 画像ファイルを渡さずに `pnpm photo:add` を実行する
- **THEN** GitHub への問い合わせを行う前に使い方を示して中断する

#### Scenario: カメラ出力の JPEG を入稿する
- **WHEN** 長辺 6000px の JPEG を `pnpm photo:add` に渡す
- **THEN** Release `photos` に長辺 2500px の `<slug>.jpg` が登録され、写真データファイルが生成される
- **AND** 生成されたファイルの `image` は `https://github.com/joe-yama/portfolio/releases/download/photos/<slug>.jpg` である

#### Scenario: 入稿規定より小さい画像
- **WHEN** 長辺 1600px の JPEG を渡す
- **THEN** 拡大されず、長辺 1600px のまま登録される

#### Scenario: 2 枚目以降の入稿
- **WHEN** 既に代表写真が 1 枚ある状態で新しい写真を入稿する
- **THEN** 生成されるファイルの `featured` は偽であり、`order` は既存のどの写真よりも後ろになる

#### Scenario: 同じ slug で写真を差し替える
- **WHEN** 人が `title` / `location` / `alt` を記入済みの写真と同じ slug で `pnpm photo:add` を実行する
- **THEN** Release の画像は新しい画像に置き換わり、写真データファイルは 1 文字も変わらない
- **AND** データファイルを変更していないことが出力に示され、終了コードは 0 である

#### Scenario: 差し替え後のビルド
- **WHEN** 同じ slug で写真を差し替えた直後にビルドする
- **THEN** ビルド出力の画像は新しい画像から生成されたものであり、古い版は残らない

#### Scenario: slug を明示する
- **WHEN** 拡張子に見える文字列を含む slug（`kamo-river-v1.2` など）を明示して入稿する
- **THEN** その値がそのまま slug として使われ、切り詰められない

#### Scenario: 撮影情報が欠けている
- **WHEN** レンズ情報を持たない JPEG を渡す
- **THEN** コマンドは「レンズ」が欠けていることを示して中断する
