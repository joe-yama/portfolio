### 1.3 ledger（再入可能性の要）

### 1.4 止まる条件（それ以外は止まらない）

`CLAUDE.md` の 4 条件のうち、今回は PO 承認により「worktree 外への副作用（push・publish・merge）」が解除されている（§5）。止まるのは次の 3 つだけ:

1. 破壊的・不可逆な操作が必要になったとき（`rm -rf`、履歴の書き換え、Release asset の削除、Issue のクローズ以外の GitHub 側の削除）
2. セキュリティ（秘密情報、`.env`、外部サービスへの送信）
3. どの道も推測になる計画の欠陥（spec も設計書もこの文書も答えを持たない）。この場合も**そのフェーズを止めるだけ**で、依存しない次のフェーズに進み、ledger と Issue に質問を書く

判断が必要な点は spec を正に裁定し、ledger の「裁定」表と change の Issue に「裁定 / 理由 / 間違っていたときの代償」を記録して進む。

### 8.3 e2e と CI の設計上の既定（裁定。Issue に記録）

- e2e は **`pnpm build` 済みの `dist/` を `pnpm preview` で配信して実行**する（`webServer` に `pnpm preview`。本番と同じ静的配信で、`base` の挙動もそのまま出る）。ブラウザは Chromium のみ
- axe は `@axe-core/playwright` で各ページに 1 回。違反 0 を assert（`impact` で絞らない）。既知の違反が出たら**修正が spec 内なら直し、spec 外なら裁定して `disableRules` ではなく該当ページの修正 change を後続に回す**（ルールの無効化はテストの期待値の書き換えに当たる）
- 内部リンク検査は e2e の 1 テスト（`dist/` を `fs` で走査。依存を足さない）か、`scripts/` の小さな Node スクリプトのどちらか。**新しい依存は入れない**
- 外部通信ゼロの検査: `page.on('request')` で `127.0.0.1` 以外のホストへのリクエストを集め、0 件を assert
- CI: `ci.yml` の `check` job に `pnpm exec playwright install --with-deps chromium` と `pnpm e2e` を追加（job 名 `check` は変えない。ruleset の required check の名前になる）
- デプロイ: `deploy.yml` は `push: branches: [main]` + `workflow_dispatch`。`permissions: contents: read / pages: write / id-token: write`、`concurrency: group: pages`。`withastro/action`（v6。README で `node-version` / `package-manager` 入力を確認し、`.node-version` と揃える）→ `actions/deploy-pages`（v5）。P0 で Pages を有効化できなかった場合だけ `actions/configure-pages` を `enablement: true` で挟む
- ローカルで `pnpm e2e` を初回に動かす前に `pnpm exec playwright install chromium`（ダウンロードが発生する。sandbox はこのマシンでは無効）

### 8.4 手順

P1 と同じ流れ（brainstorming → `/opsx:propose deploy-and-e2e` → Issue → writing-plans → worktree → SDD → ブランチ全体レビュー → PR → CI → マージ）。追加の注意:

- delta spec: `quality-gates`（e2e、リンク検査、`base` 配下の URL）を MODIFIED、`i18n-routing`（`base` を剥がしたロケール判定、リダイレクト先）を MODIFIED、新規 `deployment`（Pages への公開、workflow）を ADDED
- レビューの単位の目安: 単位 A = `base` 対応（純関数 + `.astro` の置換。**UI 実測あり**: `http://127.0.0.1:4321/portfolio/` のリダイレクト、`/portfolio/en/` の `documentElement.lang` と hreflang、ヘッダー 4 リンクの `href`、favicon の 200）、単位 B = e2e + リンク検査、単位 C = workflow 2 本、ブランチ全体 1 回
- **マージ前に** `gh pr checks` で e2e 込みの CI が緑であること。**マージ後に** `gh run list --workflow deploy.yml` → `gh run watch <id>` で成功を確認する。失敗したら `gh run view <id> --log-failed` で原因を読み、`fix/deploy-*` ブランチの PR で直す（Issue は同じ）。3 回直しても通らなければ ledger に状態を書いて P3 の検証に進み、公開できていない事実を「PO への申し送り」の先頭に書く

## 10. 既知のリスクと対策

### 10.1 bypass permissions と hook の `ask`

- `.claude/settings.json` の `permissions.ask`（`gh pr merge`、`pnpm add`、`rm`、`curl` など）と `~/.claude/settings.json` の `ask` は bypass で**出なくなる**。`deny` と、hook の exit 2（`block-destructive.sh`）は bypass でも**効く**（公式: Deny rules block in every mode）
- hook が返す `permissionDecision: "ask"`（`ask-gate.sh`: `main` への push、`--force`、`--frozen-lockfile` 無しの `pnpm install`。`~/.claude/permission-gate.sh`: `gh api` の POST / PUT / PATCH、`-f` 付き）が bypass でどう扱われるかは**未実測**。自動許可される可能性と、プロンプトが出て PO 不在で止まる可能性の両方がある。対策: (1) 該当操作は `gh api -X POST` 2 回（Pages、ruleset）だけに絞った、(2) `main` には直接 push しない（§5）、(3) `pnpm add` は `permissions.ask` なので bypass で通るが、`pnpm add -D @playwright/test @axe-core/playwright` を**1 回だけ**実行し、lockfile 更新を同じコミットに含める、(4) 止まったらその操作だけ飛ばして先に進み、申し送りに書く（§6 の 6、§9.3）
- Stop hook（`pnpm test`）は毎ターン走る。e2e を Vitest に拾わせない（§8.2）

### 10.2 コンテキストの肥大化とターン上限

- 過去の実測: 1 change あたりコントローラー 400〜600 メッセージ（`docs/harness/README.md` §6）。2 change + デプロイで 500 ターンに収まらない可能性がある。`/goal` の上限で止まったら PO が同じプロンプトで再起動する。**ledger が唯一の再開点**なので節目ごとに必ず更新する
- サブエージェントの報告全文をコントローラーの文脈に持ち込まない（報告はファイルに書かせ、判定に必要な部分だけ読む）
- `CLAUDE.md`「Compact instructions」に従う

### 10.3 サブエージェント

- `.claude/agents/*.md` の変更はセッションに反映されない。今回は**定義を変えない**
- reviewer の `maxTurns: 80`。UI 実測は brief に列挙した項目だけ。途中で partial に終わったら同じ reviewer に `SendMessage` で再開
- implementer に渡す brief には worktree の絶対パス、対象 `tasks.md` のパス、計画の「落とし穴」節、`tsconfig` の `noUnusedLocals` / `verbatimModuleSyntax` を必ず書く（過去の申し送り）

### 10.4 ビルドと外部取得

- ビルドは Google Fonts（DotGothic16）と GitHub Releases（写真 2 枚）から取得する。ネットワークが要る。CI は毎回冷えている
- 温かいキャッシュの落とし穴（`node_modules/.astro/assets` の stale cache）は写真を差し替えないので今回は踏まない。写真の差し替えはしない
- `withastro/action` が Node のバージョンを `.node-version` から読むかは README で確認し、読まないなら入力で 26 を指定する。Astro 7 の要求 Node を満たさないとデプロイ workflow だけ落ちる（CI は `actions/setup-node` で `.node-version` を読んでいる）

### 10.5 スコープの誘惑

Change 3 の提案 40 件超、`h1` の追加、`aria-label`、個別ページの `loading="eager"` などは**このリリースでは手を付けない**。例外は axe の違反として実測で出たもの（spec §7「アクセシビリティ」の範囲内なら Change 5 で直す）。
