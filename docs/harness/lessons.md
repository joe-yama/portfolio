# 実物でしか出ない欠陥と、番人の検証

単体テストが緑でも通り抜けた欠陥の記録。テストや CI が想定外の落ち方をしたとき、新しいテストを書くとき、CI まわりを触るときに読む。

## 1. 単体テストでは原理的に検出できなかった欠陥

実物で初めて見つかった欠陥は、**単体テストでは原理的に検出できなかった**ものが多い。

Change 3（photo-pipeline）の 4 件:

1. `exifr` のファイルパス経路が Node 26 で壊れる
2. `image.domains` がリダイレクト先を許可していない
3. `--slug` の無検証
4. UTC 固定のテストが CI で番人にならない

Change 5（deploy-and-e2e）の 2 件。どちらも **CI でだけ壊れる**:

1. `astro preview` は対話端末では自動デーモン化するが、CI（非対話端末）では前景実行になり `execSync` がブロックする → `--background` を明示し、`fetch` で 200 を待つ
2. 既定バインド先の `localhost` は ubuntu runner では IPv6 `::1` に解決され、`127.0.0.1` 宛の接続が拒否される → `--host 127.0.0.1` を明示する

Change 10（followup-hardening）の 3 件。いずれも**単体テストは緑のまま、実データや実プロセスでだけ壊れていた**:

1. **js-yaml がクォートの無い日付を `Date` にする。** `photoSchema.takenAt` が `z.union([z.date(), isoDate…])` だったので、`takenAt: 2025-02-30` は `z.date()` 枝で受かり、暦の `refine` に到達しないまま **2025-03-02 へ黙って繰り上がっていた**。文字列を渡す単体テストは通る（実データでは通らない道を検査していた）。`z.date()` 枝を落として文字列だけ受け、実データの YAML がクォート済みであることをテストで固定した
2. **`astro preview status` はプロジェクト root ごとのロックしか見ない。** 別ディレクトリ・別プロセスが同じポートを占有していても検出できず、`astro preview` はポート指定を無視して別ポートへ退避し、**e2e 21 件が他人のビルド出力に対して実行された**。占有判定は `fetch(baseURL)` でポートそのものを叩く形にした
3. **Playwright は globalSetup が例外を投げた実行でも globalTeardown を呼ぶ。** マーカーの有無だけで停止を決めていたため、他人の配信サーバを止めていた。マーカーに実行の識別値を書き、自分の実行が起動したときだけ止める

**結論: ローカルの緑を完了の根拠にせず、CI の実行結果を最終証拠にする。実データと実プロセスでだけ壊れる経路は、実データと実プロセスで試す。**

そのほか v1 リリース時に出たもの（`docs/harness/README.md` §4 の bypass 実測に詳細）:

- CI の job に `timeout-minutes` が無いと、ハング時に既定上限（6 時間）まで回る。実際に 20 分で PO が手動停止した。reviewer は Minor として挙げていたが、同じ CI 実行で実損化したので Important に格上げして修正した
- Biome は未追跡ファイルも検査する。`docs/runs/` へ置いた JSON の整形漏れでローカルの `pnpm lint` が落ちた（CI は未追跡なので緑のまま）

## 2. 「テストが緑」と「テストが番人」は別物

Change 9（photo-height-cap）で 2 回出た。どちらも CSS の寸法検査で、書いた本人もレビュー前の実行も気づけなかった:

1. `grid` 変種にも高さ上限を漏らす変異が、1440×900 のサムネイル検査を落とさなかった。`sizes` の推定幅 20rem = 320px が実際の列幅 約294px を上回り、`max-width: 100%` で丸め込まれていたため。800×600 = `sizes` が `33vw` になる帯を足して塞いだ
2. `max(12rem, …)` の下限を外す変異が、どの検査も落とさなかった。e2e が使う 4 つの viewport では式が常に正だったため。1280×400 の検査を足して塞いだ

Change 10（followup-hardening）でも 4 件出た。**追加したばかりの番人自身がすり抜けた**ものが 3 件ある:

1. 共有カードの e2e が 10 ページ中 2 ページしか見ておらず、画像寸法・ロケール・カード形式を変える変異が緑のまま通った
2. `readTokens` が CSS のコメントと再宣言を見抜けず、罫線が実際に 1.07 まで薄くなる CSS でもテストは緑だった
3. 経歴ページの「0 件の区画を出さない」条件分岐にテストが 1 本も無く、職歴が消えても単体 244 件・e2e 58 件のどれも落ちなかった
4. 新しく足した `parseOrder` / `hasFeaturedFlag` のテストが行頭アンカーを固定しておらず、`/^order:/m` → `/order:/m` の変異ですり抜けた

**番人を書いたら必ず変異を当てて落ちることを確かめる。** change の `tasks.md` に「番人が本当に番人か確かめる」タスクを 1 つ置く。隔離実行の手順は `docs/harness/README.md`。

## 3. Astro のスコープ CSS は複合セレクタの両側に属性を付ける

Change 10 で、`src/pages/404.astro` に書いた `main > p:last-child { … }` が**一度も適用されなかった**。コンパイル結果は `main[data-astro-cid-…] > p[data-astro-cid-…]:last-child` で、`<main>` はレイアウト側の要素なのでスコープ属性を持たない。

レイアウト側の要素を指すときは `:global(main) > p:last-child` と書くか、そのページ自身の要素だけでセレクタを閉じる。**「CSS を足したのに見た目が変わらない」ときは、まずビルド出力のインライン CSS で実際のセレクタを見る。**
