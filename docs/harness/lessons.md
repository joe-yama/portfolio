# 実物でしか出ない欠陥と、番人の検証

単体テストが緑でも通り抜けた欠陥の記録。テストや CI が想定外の落ち方をしたとき、新しいテストを書くとき、CI まわりを触るときに読む。

## 1. 単体テストでは原理的に検出できなかった欠陥

実物で初めて見つかった欠陥は、**単体テストでは原理的に検出できなかった**ものが多い。

Change 3（photo-pipeline）の 4 件:

1. `exifr` のファイルパス経路が Node 26 で壊れる
2. `image.domains` がリダイレクト先を許可していない
3. `--slug` の無検証
4. UTC 固定のテストが CI で番人にならない

Change 5（deploy-and-e2e）の 2 件。どちらも **CI でだけ壊れる**:

1. `astro preview` は対話端末では自動デーモン化するが、CI（非対話端末）では前景実行になり `execSync` がブロックする → `--background` を明示し、`fetch` で 200 を待つ
2. 既定バインド先の `localhost` は ubuntu runner では IPv6 `::1` に解決され、`127.0.0.1` 宛の接続が拒否される → `--host 127.0.0.1` を明示する

**結論: ローカルの緑を完了の根拠にせず、CI の実行結果を最終証拠にする。**

そのほか v1 リリース時に出たもの（`docs/harness/README.md` §4 の bypass 実測に詳細）:

- CI の job に `timeout-minutes` が無いと、ハング時に既定上限（6 時間）まで回る。実際に 20 分で PO が手動停止した。reviewer は Minor として挙げていたが、同じ CI 実行で実損化したので Important に格上げして修正した
- Biome は未追跡ファイルも検査する。`docs/runs/` へ置いた JSON の整形漏れでローカルの `pnpm lint` が落ちた（CI は未追跡なので緑のまま）

## 2. 「テストが緑」と「テストが番人」は別物

Change 9（photo-height-cap）で 2 回出た。どちらも CSS の寸法検査で、書いた本人もレビュー前の実行も気づけなかった:

1. `grid` 変種にも高さ上限を漏らす変異が、1440×900 のサムネイル検査を落とさなかった。`sizes` の推定幅 20rem = 320px が実際の列幅 約294px を上回り、`max-width: 100%` で丸め込まれていたため。800×600 = `sizes` が `33vw` になる帯を足して塞いだ
2. `max(12rem, …)` の下限を外す変異が、どの検査も落とさなかった。e2e が使う 4 つの viewport では式が常に正だったため。1280×400 の検査を足して塞いだ

**番人を書いたら必ず変異を当てて落ちることを確かめる。** change の `tasks.md` に「番人が本当に番人か確かめる」タスクを 1 つ置く。隔離実行の手順は `docs/harness/README.md`。
